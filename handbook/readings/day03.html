1359### 7.5.1 工具基类与注册机制设计
1360
1361在构建可扩展的工具系统时，我们需要首先建立一套标准化的基础设施。这套基础设施包括Tool基类、ToolRegistry注册表，以及工具管理机制。
1362
1363（1）Tool基类的抽象设计
1364
1365Tool基类是整个工具系统的核心抽象，它定义了所有工具必须遵循的接口规范：
1366
1367````python
1368class Tool(ABC):
1369 """工具基类"""
1370
1371 def __init__(self, name: str, description: str):
1372 self.name = name
1373 self.description = description
1374
1375 @abstractmethod
1376 def run(self, parameters: Dict[str, Any]) -> str:
1377 """执行工具"""
1378 pass
1379
1380 @abstractmethod
1381 def get_parameters(self) -> List[ToolParameter]:
1382 """获取工具参数定义"""
1383 pass
1384````
1385这个设计体现了面向对象设计的核心思想：通过统一的`run`方法接口，所有工具都能以一致的方式执行，接受字典参数并返回字符串结果，确保了框架的一致性。同时，工具具备了自描述能力，通过`get_parameters`方法能够清晰地告诉调用者自己需要什么参数，这种内省机制为自动化文档生成和参数验证提供了基础。而name和description等元数据的设计，则让工具系统具备了良好的可发现性和可理解性。

1403

1407class ToolRegistry:

1417 print(f"⚠️ 警告:工具 '{tool.name}' 已存在，将被覆盖。")
